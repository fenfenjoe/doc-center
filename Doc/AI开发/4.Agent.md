## 技术栈

| 功能 | 技术 |
| --- | --- |
| 编程语言 | python、TypeScript |
| Agent搭建组件（Framework） | langchain（组件）、CrewAI|
| Agent运行时组件（Runtime）| langgraph（编排器）|
| Agent集成组件（Harness）| DeepAgents|
| 容器化部署 | Docker |

常用的Agent搭建框架：

| 框架 | 开发者/定位 | 语言 | 核心理念与优势 | 适用场景 |
|------|------------|------|---------------|---------|
| LangGraph | LangChain (低级别运行时) | Python, TS | 基于图的状态机、持久化执行、高度可控。 | 需要精细控制流程和状态的生产级复杂应用。 |
| DeepAgents | LangChain (高级封装) | Python | 高级"驾驭"工具，内置规划、反思等能力，构建"深度"智能体。 | 需要自主规划和决策的复杂长时运行任务。 |
| CrewAI | 独立社区 | Python | 角色扮演、"团队"协作、轻量级编排。 | 多角色协作的自动化流程（如客服、调研团队）。 |
| Microsoft Agent Framework (MAF) | Microsoft | Python, .NET | 统一框架，结合了 Semantic Kernel 的企业级特性和 AutoGen 的多智能体创新。 | 需要与微软生态（.NET, Azure）深度集成的企业级应用。 |
| Claude Agent SDK | Anthropic | Python, TS | 深度 MCP 集成、内置文件系统/Shell 访问，擅长与真实计算机交互。 | 需要操作本地文件、运行代码的代码或研究助手。 |
| OpenAI Agents SDK | OpenAI | Python, TS | 围绕 Handoffs（任务移交）和 Guardrails（安全检查），设计简洁。 | 需要轻量级多任务切换的场景（如客服机器人）。 |
| Google ADK | Google | Python, TS, Java, Go | 官方支持多语言（4种），提供类似 LangGraph 的编排能力。 | 需要将 Agent 深度集成到 Java/Go 等既有企业服务中。 |
| Smolagents | Hugging Face | Python | 以代码为导向，让 Agent 编写代码来解决问题。 | 数据分析、文件批处理等以"代码生成与执行"为核心的任务。 |
| Pydantic AI | Pydantic 团队 | Python | 利用 Pydantic 的验证能力，保证 Agent 输入输出结构的强类型安全。 | 对数据质量和格式严格性有极高要求的 API 或数据处理任务。 |
| Haystack | deepset | Python | 深度集成 RAG 管道，Agent 可以作为管道中的组件。 | 知识密集型应用（如企业文档问答、研究报告生成）。 |
| Mastra | 独立社区 | TypeScript | TypeScript 原生框架，提供完整的 Agent 开发及部署能力。 | 偏好 TypeScript 技术栈，追求统一技术栈的开发者。 |



## 开发环境搭建

1. 安装node.js

```bash
# 安装 nvm（macOS / Linux）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 重新加载 shell 配置（或重启终端）
source ~/.bashrc   # 如果使用 bash
# 或 source ~/.zshrc

# 安装 Node.js 20 LTS（推荐用于 Agent 开发）
nvm install 20
nvm use 20
nvm alias default 20

# 检查是否安装成功
node --version   # 应输出 v20.x.x
npm --version    # 应输出 10.x.x 或更高
```

2. 安装pnpm（可选）

```bash
# 全局安装 pnpm
npm install -g pnpm

# 验证安装
pnpm --version
```

3. 获取大模型API Key

略

4. 初始化项目

```bash
mkdir my-awesome-agent
cd my-awesome-agent
npm init -y
```

5. 初始化TypeScript配置

```bash
npx tsc --init
```

6. 安装核心依赖

```bash
# 安装LangGraph核心依赖（环境数据暂存）
npm install @langchain/langgraph @langchain/core @langchain/openai

# 安装TypeScript开发依赖
npm install -D typescript ts-node @types/node dotenv
```

7. 编写你的Agent代码

略

8. 调试

（1）使用ts-node快速执行
```bash
# 假设你的Agent入口为index.ts
npx ts-node index.ts
```

（2）使用 LangGraph CLI 和 Studio 获得可视化调试体验

```bash
#安装CLI
npm install -g @langchain/langgraph-cli
#启动服务器
langgraph dev
```

9. 部署（Docker）

（1）使用Express 框架，将Agent封装成一个 Web API，详情略  

（2）编写 Dockerfile  

（3）确保 package.json 中有 build 脚本：  
```json
"scripts": {
  "build": "tsc",
  "start": "node dist/server.js"
}
```

（4）构建容器  
```bash
docker build -t my-agent:latest .
```

（5）运行容器  
```bash
docker run -d --name my-agent \
  -p 3000:3000 \
  -e OPENAI_API_KEY="你的API密钥" \
  my-agent:latest
```

10. 测试API

```bash
curl -X POST http://localhost:3000/ask \
  -H "Content-Type: application/json" \
  -d '{"message": "你好，Agent！"}'
```

## workflow pattern

LangGraph 官方文档中总结了5个核心 **Agentic Workflow Pattern**，它们分别描述了如何组织和编排多个 LLM 调用（或 Agent 节点）来完成复杂任务。简单理解，它们就是设计 AI Agent 系统的“流程模板”。

1. Prompt Chaining（提示链）  

**一句话概括：** 上一个环节的输出，作为下一个环节的输入，线性执行。

**优点：** 简单可控，每一步可以独立优化提示词。

**缺点：** 总延迟累加，前一步的错误会向后传播。

2. Routing（路由）  

**一句话概括：** 根据输入的分类，动态选择不同的后续处理流程。

**优点：** 将关注点分离，每个下游处理单元可以高度优化。

**缺点：** 路由模块的判断准确率是系统瓶颈。

3. Parallelization（并行化）

**一句话概括：** 同一份输入同时送给多个处理单元，然后将结果合并。

**优点：** 降低延迟（理论上），提高答案的全面性和鲁棒性。

**缺点：** 合并逻辑可能复杂，计算资源消耗较高。

4. Orchestrator-Worker（编排器-工作器）

**一句话概括：** 一个中心化的“主管”动态拆分任务，分配给多个“打工人”，并汇总结果。

**优点：** 处理高度复杂的任务，适应性强。

**缺点：** 实现复杂，Orchestrator 需要强大的规划和总结能力，可能产生高 token 消耗。

5. Evaluator-Optimizer（评估器-优化器）

**一句话概括：** 一个“生成器”产生方案，一个“评估器”给出反馈，循环迭代改进。

**优点：** 可以产出极高品质的结果，类似人类的“反思”过程。

**缺点：** 延迟和 token 消耗不确定，循环可能发散或不收敛。
